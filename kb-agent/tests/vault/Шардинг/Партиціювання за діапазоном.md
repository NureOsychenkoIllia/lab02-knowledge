# Партиціювання за діапазоном

Ключі ділять на неперервні діапазони, і кожен вузол відповідає за свій діапазон. Усередині партиції ключі відсортовані, тому діапазонні запити читаються послідовно й ефективно.

## Як працює

Bigtable ділить таблицю на планшети, HBase — на регіони, MongoDB — на чанки; межі задають за ключем сортування, а не за хешем. Запит «усі замовлення за березень» для ключа (user_id, created_at) перетворюється на один послідовний скан, а не на пошук по всіх вузлах. Вузький діапазонний скан дешевший за точкові запити до багатьох партицій.

## Гарячі точки

Якщо ключ зростає монотонно — мітка часу, автоінкрементний ідентифікатор, — усі записи потрапляють в одну партицію й один вузол стає вузьким місцем. Класичне лікування — складені ключі: префікс із дати, хешу або ідентифікатора пристрою розкладає записи по партиціях, а читання за префіксом лишається діапазонним. Інший варіант — заздалегідь розділити гарячий діапазон на кілька частин.

## Обмеження

Нерівномірність діапазонів переносить навантаження на окремі вузли, тому потрібне [[Ребалансування партицій]]. Діапазонний скан за ключем, що не є префіксом, перетворюється на опитування всіх партицій. Порівняно з [[Хеш-партиціювання]] схема програє в рівномірності запису, але виграє в запитах за діапазоном.
